# 0.16.0：立即领取、报告问题，以及把「点了没反应」修透

这是 0.15.10 之后的第一个正式版本。内部测试号 `0.15.11.1` 从未公开发布，
它的全部改动都在这个版本里。重点有两块：**新增两个能直接用的入口**，
以及**把「点击领取后积分不涨」这条链路上的问题一次修完**。

---

## 一、账户详情页新增「🎁 立即领取」

在「刷新状态」旁边。点一下只做领取这一件事，不跑签入、阅读、搜索。

它**不受任何隐式条件影响**：不看「定期收取积分」开关、不看定时节奏、不看阈值、
也不看今天是否失败过，并且不写任何时间戳（写 `lastClaimDate` 会污染定时间隔计算）。

结果会同时出现在账号日志里，并推送一条「🎁 立即领取结果」——
成功、当前没有待领取、领取未成功三种情况都会推。

## 二、收取节奏新增「遵循下方阈值执行(默认)」

下拉现在是三项，各只显示自己需要的输入框：

| 选中 | 显示 | 隐藏 |
|---|---|---|
| 遵循下方阈值执行(默认) | 阈值框（默认 300 分） | 间隔天数、每天几点 |
| 每隔 N 天 | 间隔天数 | 阈值框 |
| 每天定时 | 每天几点 | 阈值框 |

选了阈值模式后，后台的定时节奏会**真的跳过**，不是只把界面换了个样子。
整块设置始终可见；「定期收取积分」开关关闭时会明确提示「本项不会生效」，不会把入口藏起来。

## 三、软件设置 → 更新下面「报告问题」

一键把日志打包成 zip，方便排查问题时发给开发者。

- 时间段：今天 / 24 小时内 / 48 小时内 / 72 小时内 / 这个星期 / 这个月 / 所有 / 自定义
- 自定义时展开年 / 月 / 日选择器（排成一行、带展开动画），**没有日志的日期置灰不可选**
- 「隐藏敏感信息（脱敏）」**默认关闭**；打开后自动隐藏账号 ID 与推送地址里的密钥
  （钉钉 token、企微 key、Bark 设备串等）
- 导出为 zip，文件名自动附加当前时间与内容哈希；先弹窗询问保存在哪
  （Web/Docker 版由浏览器下载）
- 导出完成后会提示：文件可能包含隐私数据，请妥善保存、不要随意分享

## 四、领取「点了但积分不涨」的几处修复

这段时间收到的日志显示，问题不是一个，而是几个叠加：

1. **点到的是整张卡片**，不是「领取」按钮。现在按文本长度与面积打分，
   含数字或「可领取」字样的整卡会被重罚，并把候选清单写进日志。
2. **对话框识别误判**：`[data-rac]` 是 React Aria 挂在所有组件上的通用属性，
   旧逻辑取第一个可见元素当对话框，常常拿到空壳。现在只认真正的对话框语义，
   遍历全部候选、补上英文匹配，并处理 iframe 里的弹窗。
3. **确认按钮以数字开头**：真实按钮文案是「2,845 待领取 领取积分」，
   旧规则要求以「领取」开头 → 一个都匹配不上，随后兜底误点了导航栏的「兑换」。
   现在改为分级匹配，主文档 / iframe / 落地页共用一份规则，并且都用真实鼠标点击。
4. **手动入口的日志与推送缺失**：手动领取不经任务主循环，日志没归属账号
   （详情页看不到），也没有结果推送。现在都已补齐。

另外，IP 查询失败时不再一律报「空响应」——超时、DNS 失败、TLS 失败、
被网关劫持会分别说清楚。

## 五、升级提示

- 桌面 Rewards 应用专属任务**仍暂缓上线**：入口置灰并标「测试中 · 延迟上线」，
  探测与执行都被拦住，推送汇总也不再输出该行。等测试完成会单独说明开放时间。
- 旧配置里没有阈值字段时，会回落到默认 300 分；只有**显式填 0** 才是主动关闭。
- 之前开过 Windows Hello 的话，若 PIN 解锁提示「没有免密凭据」，**用密码解锁一次**即可自动重建。
- 更新包签名是强制校验的，本次 Release 已签名；若「检查更新」提示签名失败，请先确认网络代理没有改写页面内容。
