# 0.14.8：版本号统一 + CodeQL 清零

> 上一版 0.14.7 的三个修复（版本号分叉、最后一条 CodeQL 告警、CI 守卫数据入库）现在都进安装包了。

## 版本号不再一个窗口两个数

你在界面上应该遇到过这种情况：标题栏写着 `v0.14.6.1`，左边侧边栏底下却是 `0.14.5`。

原因是这个项目里版本号有**两个来源**——标题栏读的是运行时的 `package.json`，而侧边栏和关于页用的是前端**在打包那一刻烧进 JS 的常量**。开发时改了版本号但忘了重新构建前端，常量就停留在旧值，两处自然对不上。

| 位置 | 改前 | 改后 |
|---|---|---|
| 标题栏 | 运行时读 `package.json` | 不变 |
| 侧边栏左下角 | 编译期常量（会漂移） | 运行时真值 |
| 关于页 | 自声明常量（连version.ts 都不 import） | 运行时真值 |
| 更新面板 / 更新弹窗 | 编译期常量 | 运行时真值 |

现在四个展示位统一向主进程取真值，编译期常量只作为预览环境的回落值。顺带说明：以后你在任何一个界面看到的版本号，都等于真实安装的版本。

## 安全：最后一条 CodeQL 告警清零

深度合并配置的那段代码补上了显式的 `hasOwnProperty` 守卫。

有个细节值得一提：只在循环里跳过 `__proto__` / `constructor` / `prototype` 这几个危险键**并不足以让静态分析认账**——它的判定逻辑是「从不可信对象读值→ 往目标对象写属性」这一对动作，光靠黑名单跳过仍会被标记。这也是为什么之前明明加了防护、告警却还挂着。

## CI：一条一直在假绿的守卫

顺带修掉一个隐蔽问题：有条校验「发布说明里用到的 Markdown 语法渲染器都认得」的守卫，它的测试样本被放在了被 `.gitignore` 排除的目录里。

- **后果**：本地永远绿、CI 永远红，而红的原因与代码质量毫无关系
- **修法**：样本移入 `scripts/fixtures/` 正常入库，并新增前置守卫
- **收益**：把「读不到样本」和「语法不支持」两种失败明确区分开，省掉下一次误判
