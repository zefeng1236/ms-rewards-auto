# 0.14.10：环境拟真面板布局重排

> 纯界面调整，不改任何运行逻辑。配置与账号数据不受影响，直接覆盖安装即可。

按反馈重排了「软件设置 → 浏览器」里**环境拟真**那一块的字段布局。此前这块
控件的位置比较混乱：几个下拉框和数字输入框混在一起，内核切换卡片被挤成上下
两张，「只保留单个内核」开关夹在中间谁也不属于，看着最突兀。

## 改了什么

### 两张内核卡片并排同一行

内核选择是「当前用哪个内核」的二选一 —— 默认的 **Chromix 154** 与备用的
**fingerprint-chromium 150**（上游 canvas 崩溃缺陷未修，当前灰显不可选）。

现在两张卡片**占满整行、并排同一行**：选中的高亮带「当前」标记，不可用的灰显
并把缺陷原因挂在悬浮提示里。一眼能看出这是二选一，而不是两个并列的输入框。

### 「只保留单个内核」开关独占一行

之前它混在内核卡片与输入框之间，既不像开关组的一部分，也不属于内核卡片。现在
单独一行，标签在左、开关在右。

### 三个下拉菜单放一起

**浏览器品牌** / **声明操作系统** / **下载镜像源** 归到同一行 —— 这三个都是
"选一个值"的下拉，放一起符合直觉。

### 拟真种子下移

**拟真种子** 与 **CPU 核数** 同在最后一行，两个数字输入成对。

> 布局为实测确认，不是照着源码推的：在实际渲染里量了每个控件的坐标 ——
> 内核卡片整行 818px、两张卡各 404px 并排（x=263 / x=677，同一 y）；
> 开关独占一行；三个下拉同排；两个数字框同排。

## 顺带修的一处预览环境问题

浏览器里预览界面时（`npm run dev:web`）**永远只看到一张内核卡片**，
原因是预览用的假后端没有下发内核清单，界面走了"只有默认内核"的回落分支 ——
而真实运行环境是下发两个的。已让假后端与主进程对齐，**预览所见即真实所得**。
