# 0.17.1：通知点了真的会打开软件，每天做多少次交给服务器决定

这一版集中在两件你实际会遇到的事：**0.17.0 点了通知没反应、软件也不打开**，以及
**每天该搜多少次、读多少篇不该由代码写死**。另外给桌面任务的通知加了场景感知，
不会在你全屏打游戏、看视频，或者只是挂着动态壁纸的时候反复弹。

> ⚠️ 这是修复版本，需要**手动下载安装（会弹 UAC）**才生效。0.17.0 不会自动变成这一版。

---

## 一、点通知现在会打开软件并授权执行

0.17.0 的通知是最简结构：没有 `launch`、没有 `activationType`，点击完全依赖 Windows 按 AUMID
找激活器；而这台机器的快捷方式缺少 `ToastActivatorCLSID`、注册表里也没有对应 AUMID，
于是点击时系统既不把请求交给运行中的进程、也不拉起新进程 —— 表现就是「没反应、软件也没打开」。

现在改成：

- 应用启动时注册**用户级 `msrewards://` 协议**（只在安装版注册，避免开发环境抢占正式版）；
- 通知改用 WinRT 原生 Toast，带 `launch=msrewards://desktop-authorize`；
- 点击后 Windows 用 URL 协议拉起应用，**不带 Chromium 会拒绝的 `-Embedding` 参数**，
  进程能正常跑到业务逻辑 → 打开主窗口 → 按授权执行桌面任务；
- 原生 Toast 发不出去时自动回落原来的 Electron 通知，不会没通知。

原来的「待授权 30 分钟时间窗」仍然保留：看到通知后不点它、直接双击图标或点托盘
「显示主窗口」，在 30 分钟内同样算授权。

## 二、每天做多少次，改成服务器说了算

之前有几处把服务器给的动态值又写死：`max || 30`、`max > 0 ? max : 15`，日志里会出现
「本轮计划搜索 6 次（剩余 3 次）」，月末额度被压缩时还会白跑。现在：

- 严格区分「服务器**明确给 0**」和「字段缺失」：前者按 0 跳过，后者才用兜底值；
- 每轮搜索/阅读次数以服务器「今天还需要的次数」为**硬上界**，不会再空转；
- 上限被压缩（`originalMax > max`）时日志会明确提示；
- 阅读与搜索次数都由积分按 3 分/次、3 分/篇换算，不再假设固定 30 分 / 60 分。

**月末封顶也不再整月零行为**：服务器明确说今天额度为 0 时，汇总如实写
「当月无需执行计分任务」，但仍维持每日随机 **10–20 次搜索 + 10–20 篇阅读**的保活
（同一天目标固定、中断续跑、跑满即停、不计分、不做积分复核）。

## 三、手机端那 60 分是怎么回事

用手机 Bing App + 抓包核对了本人账号：国区（金牌 Level3）**只有一个统一搜索池**，
任务卡是 `WW_NewLevel3_search_PC`（每天最多 60 分、每次搜索 3 分），
与软件日志里的 `PC搜索=60/60` 是同一个额度 —— 手机端显示的 60 分不是额外的一池，
`移动搜索 0/0` 是正确值。

据此撤掉了按其它区服脚本结构写的额度补拉（那会把搜索切到从未验证过的移动 UA 路径，
重复计同一个池甚至触发风控），改成从手机端 `dapi/me` 的搜索任务卡读真值，
仅在 earn 页解析失败时兜底。截图里「必应 Star 奖励 2100/2100」是独立的月度权益计划，
与每天 60 分搜索互不冲突。

## 四、弹窗不再打断你（也不被壁纸骗）

- **1 小时内连续超过 3 次通知没人点** → 自动静默 2 小时；可选开关
  「1小时内多次未响应弹窗自动运行」（默认关闭），开启后改为不弹窗、自动执行一次。
- **全屏且 CPU ≥60% 或 GPU ≥50%**（满足其一即可）→ 跳过弹窗。
- **系统勿扰 / 全屏放映 / 专注助手**，或 **GPU 视频编解码引擎持续工作** → 跳过弹窗。
- 视频解码会**归因到前台进程**：Wallpaper Engine / Lively 这类动态壁纸常年在硬解，
  现在不算「你在看视频」，它们占的 GPU 也从总负载里剔除，避免通知被永久抑制。
- 探针读不到、超时或非 Windows 一律 **fail-open 放行**，不会把「先通知」模式卡死。

## 五、其它修复

- `verify:pack` 原来从工作区 `gui-react/index.html` 取资源名、却去 asar 包里找文件，
  本地构建换了哈希而 `dist/` 还是旧包时会直接崩；改为读包内自己的 `index.html`。
- 场景抑制的 CPU/GPU 判定由「且」改成「或」（全屏前提保留）。
- 离线回归扩充到 14 个脚本、selfcheck 1200 条守卫、39 条反例（逐条注入旧值验证能变红）。

## 升级提示

- 桌面任务的默认行为仍是「先通知」，本版没有改动三档触发方式与每日手动额度。
- 首次升级后请**点一次通知**验证能否唤起软件；若仍无反应，检查是否被安全软件拦截了
  `msrewards://` 协议注册，并告诉我是哪一步。
- 桌面任务仍标注「实验性功能」，请自行评估账号风险。
