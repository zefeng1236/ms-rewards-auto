# 0.17.1

发布日期：2026-11-25 · 修复版本 · 需手动下载安装（UAC 提权），0.17.0 不会自动升级为本版。

## 新增

- **协议激活的系统通知**：启动时注册用户级 `msrewards://` 协议（仅打包版），通知改用 WinRT 原生 Toast（`launch` + `activationType=protocol`）。点击通知由 URL 协议拉起应用、打开主窗口并授权执行桌面任务；原生 Toast 不可用时回落 Electron 通知。
- **弹窗无响应限流**：1 小时内连续超过 3 次通知未响应，静默 2 小时。抑制期按绝对时间戳落盘，跨天与重启不清零；用户授权后连续计数清零。
- **「1小时内多次未响应弹窗自动运行」开关**：默认关闭，仅「先通知」模式显示（设置 → 任务全局设置 → 桌面任务触发方式，标实验性）。开启后触发限流时改为自动执行一次，不再弹窗。
- **用户场景抑制**：
  - 前台窗口全屏且 CPU ≥60% 或 GPU ≥50%（满足其一）→ 跳过弹窗；
  - 系统勿扰 / 全屏放映 / 专注助手，或 GPU 视频编解码引擎连续两次采样活跃 → 跳过弹窗；
  - 视频解码按前台进程归因，动态壁纸进程（Wallpaper Engine / Lively 等）排除，其 GPU 占用不计入总负载；探针失败、超时或非 Windows 一律放行。
- **月度封顶后的每日保活**：服务器明确返回当日额度为 0 时，汇总标记「当月无需执行计分任务」，仍按天随机执行 10–20 次搜索 + 10–20 篇阅读（目标当天固定、中断续跑、跑满即停、不计分、不做积分复核）。

## 改进

- **每日次数以服务器为准**：区分「明确给 0」与「字段缺失」；每轮搜索 / 阅读次数以服务器剩余额度为硬上界；积分按 3 分/次、3 分/篇换算；上限被压缩（`originalMax > max`）时写入日志。
- **统一搜索池校验**：从 `dapi/me` 的 `type=search` 任务卡读当日上限，仅在 earn 页解析失败时兜底（复用同一请求）；服务器明确给 0 的封顶信号不被缓存覆盖。兼容 Level2 的 30 分卡、丢弃脏上限、排除抽奖卡，并保留对存在独立移动端额度池区服的兼容。撤销基于其它区服结构的 `counters.mobileSearch` 补拉。
- **场景抑制的 CPU / GPU 判定由「且」改为「或」**，全屏前提保留；单项读数缺失时另一项达标仍生效。

## 修复

- **0.17.0 点击通知无响应、未拉起应用**：Electron 最简通知缺少 `launch` / `activationType`，快捷方式无 `ToastActivatorCLSID`、注册表未登记对应 AUMID，Windows 找不到激活目标。改为协议激活。
- **动态壁纸导致通知被永久抑制**：常驻视频硬解被误判为「正在看视频」。
- **额度压缩时白跑**：阅读 `max || 30`、搜索 `max > 0 ? max : 15` 把服务器明确给的 0 当作字段缺失，回落到默认次数。
- **`verify:pack` 资源索引取错**：从工作区 `gui-react/index.html` 取资源名、却到 asar 包内查找，构建哈希变化且 `dist/` 为旧包时报 `ENOENT`；改为读取包内自身的 `index.html`。

## 升级须知

- 桌面任务默认仍为「先通知」，三档触发方式与按账号每日手动额度未改动。
- 通知发出后 30 分钟内通过其它方式打开应用，同样按授权执行（待授权时间窗保留）。
- 桌面任务标注「实验性功能」。
