# 0.15.2：安全中心、更新包签名、推送设置重做

这一版做了几件「平时看不见、出事时才知道有没有」的事：

- **安全中心**：路径边界 / 操作审计 / 三档策略，回答「这软件到底动了我什么」；
- **更新包签名**：更新检查从「防损坏」升级到「防投毒」；
- **推送设置重做**：从一长列内联配置改成弹窗 + 供应商状态点，一屏看清谁开着谁没配。

另有跨客户端汇总（默认关闭）、钉钉加签与 @人，以及一批修复。

---

## 一、安全中心（三层）

### 第一层 · 路径边界

修了三个**现在就存在**的真问题：

- `storage-path.resolve` 是纯 `path.join`，`..` 会被正常拼接 —— 全项目
  **49 处删除操作**共用它。现在越界即拒。
- 账户 id 没有校验：删除账户时收到一个 `..` 就是**递归删除 accounts 之外的
  整个目录**。现在只接受 36 位小写 UUID（id 本来就是程序自己生成的）。
- 界面传来的安装包路径直接交给 `shell.openPath`，现在必须落在 updates 目录内。

### 第二层 · 操作审计

六类「出了事一定会想知道」的落点全部记账：越界被拒、账户删除、依赖安装
（全项目唯一会触发 UAC 的操作）、指纹包装解压、导航拦截、安装包路径拒绝。

设计上有三条自我约束：**写失败绝不抛**（审计是旁路，磁盘满不能把主流程带崩）、
**不假装防篡改**（文件就在本地，真拿到写权限的人改了照样能改，不演这出戏）、
**默认过滤程序自己的缓存目录**（一次内核切换能产生几百条删除记录，全记下来
会把真正的记录淹掉）。

### 第三层 · 三档策略

`ask`（拒绝 + 留待办 —— 桌面软件没有「等待审批」的交互位置，与其弹一个没人看的
框，不如拒绝并留痕）/ `auto`（默认，放行但记审计）/ `full`（全放行）。

**策略不覆盖路径边界**：越界在任何档位都被拒。策略管的是「合法的事要不要问」，
越界是「不合法」，两件事。`full` 档下越界拒绝也照样记审计。

## 二、更新包 Ed25519 签名（供应链）

原来的哈希校验是**防损坏，不防投毒**：能改 GitHub Release 的人（账号被盗、
token 泄露），可以把安装包和 SHA256 一起换掉 —— 校验就成了自己证明自己。

从本版开始，发布说明里带一段 Ed25519 签名（HTML 注释，不影响阅读），
公钥硬编码在客户端里（随安装包分发，改不了），私钥只在 CI。签名对不上、
keyid 不认识、文件名对不上 → **一律拒绝更新**（fail-closed）。

一个细节：验签通过的哈希由主进程自己缓存，下载时只认缓存 ——
界面上伪造一个哈希没有任何用。

> 注：已安装的旧版本还不认识这个机制（继续按哈希校验升级）；从
> 0.15.2 起所有新版本都会验签。

## 三、推送设置重做

推送通知设置从一长列内联配置，改成「段标题右侧『编辑』按钮 + 弹窗双栏」：

- 左栏：各推送通道（企业微信 / 钉钉 / 飞书 / PushMe / Bark）+「推送附加一言」；
- 右栏：选中项的详细配置；
- 状态点三色：🟢 已启用 · 🟠 已配置未启用 · 🔴 未配置。

每个通道新增独立启用开关。升级用户的旧配置**默认全开**，行为不变。

## 四、跨客户端汇总（默认关闭）

多台客户端把完成情况推到同一个钉钉群时，群消息是时间流 —— 看一屏只知道
最近几条，谁漏做了一目了然不了。

现在可以把一台设为**汇总机**、其余设为**客户端**：客户端定时上报账户状态，
汇总机定期把「谁在线、谁做满、谁漏做」整理成一份结构化报告发进群
（也可以随时手动生成）。在设置「跨客户端汇总」里配角色与地址，**不配置就不启动**。

---

## 五、钉钉加签认证 + @人

钉钉推送原来只有关键词一种安全模式；现在支持：

- **加签**（HMACSHA256），与关键词可同时开；
- **@手机号**（上限 20 个，自动归一化去重）。

## 其他修复与加固

- 更新弹窗不再显示发布说明里的签名块（HTML 注释在自己写的 markdown 渲染里
  会当普通文本露出来）；验签逻辑不受影响，仍对原始正文生效；
- 弹窗宽度改回按尺寸档位固定（上一版改成自适应后，内容少的弹窗被撑满）；
- CodeQL 通报的净化链不完整（#18/#19）：裸尖括号剥离补上；
- 渲染进程显式声明沙箱，并补 `will-navigate` 拦截；
- 一组守卫强化与新增（主进程 JS 语法解析、fail-closed 逐分支锚定、
  审计锚定调用点等），全部配反例验证。

## 升级说明

直接覆盖安装即可，配置与账户数据不受影响。

Docker 部署：

```bash
docker compose pull && docker compose up -d
```
