# 0.15.7：依赖安全更新（21 条告警清零）

纯安全更新版本，**无功能变更**：把 Dependabot 挂着的 21 条告警（10 high / 8 medium / 3 low）清零。

全部在现有 semver 范围内升 patch 版，`package.json` 的依赖范围没动，只有 `package-lock.json` 变化
——运行时任务逻辑、指纹参数、内核版本都与 0.15.6 完全相同。

## 升级了哪些

| 包 | 旧 → 新 | 告警 | 内容 |
|---|---|---|---|
| `undici` | 6.29.0 → **6.29.1**<br>7.30.0 → **7.30.1** | 9（5 high） | TLS 证书校验被丢弃导致**绕过**、跨源重定向缓存投毒、TLS 1.2 重协商 DoS |
| `vite` | 8.3.2 → **8.3.5** | 6（1 high） | `launch-editor` 的 `fs.existsSync()` 检查在 Windows 上可绕过 → 任意命令执行；`server.fs.allow` 越界读 |
| `fast-uri` | 3.1.8 → **3.1.9** | 4（2 medium） | 百分号编码 scheme 解码导致 URI scheme 欺骗、host canonicalization 绕过 |
| `electron` | 44.5.1 → **44.10.0** | 1（high） | 针对 eMudhra 中间证书被入侵的缓解 |
| `http-cache-semantics` | 4.2.0 → **4.3.0** | 1（high） | `max-stale` 处理不当 → 跨用户缓存响应泄露 |

`undici` 有两份：6.x 来自 `electron-builder → @electron/rebuild → node-gyp`，7.x 来自
`electron → @electron/get`，两条链都升到了各自的修复版。

## 对使用没有影响

- 内核仍是 **Chromix 155.0.8059.79**，启动参数、指纹策略一字未改；
- 界面、任务逻辑、推送格式都不变；
- 唯一的直接感受是 Electron 外壳从 44.5.1 升到 44.10.0（Chromium 侧安全修复），
  如果之前遇到过证书相关的偶发报错，这一版会更稳。

> 顺带说明：`npm audit` 在国内镜像（npmmirror）上不可用——镜像不实现 audit 端点，
> 返回 `[NOT_IMPLEMENTED]`。所以这次是按 Dependabot 告警里给出的修复版本定向升级的。
