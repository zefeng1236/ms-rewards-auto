# 0.15.6：内核升到 Chromix 155，容器 WebGL 换成真显卡

一个「环境真实性」版本，两件事，都不改变任务逻辑，只让浏览器更像一台真实的机器。

---

## 一、环境拟真内核：Chromix 154 → **155.0.8059.79**

上游 2026-10-20 发布（231 个 patch）。与本项目相关的修复：**启动时区同步**——本项目靠
`--fingerprint-timezone` 伪装时区，之前存在「启动阶段取到宿主时区」的窗口；另有 PNG 导出与
`WebString::FromUtf8` 修复。

真机实测（`chrome.exe` FileVersion = 155.0.8059.79，SHA256 与上游 digest 一致）：

- `login.live.com` / `rewards.bing.com` / `www.bing.com` 三域正常加载，渲染进程 **零崩溃**；
- 伪装逐项生效：UA `Chrome/155.0.x`、brands `Google Chrome/155`、tz `Asia/Shanghai`（−480）、
  lang `zh-CN`、`webdriver=false`、plugins 5、cores 8；
- **154 vs 155 逐项对照完全相同**（WebGL / Canvas / Audio 矩阵，含同种子的 canvas 噪声哈希）
  → 存量账户指纹不会突变，升级无感。

`--fingerprint-*` flag 契约无破坏性变更，启动参数不用改。

## 二、容器部署：WebGL 不再是 SwiftShader

Docker 里原本报
`ANGLE (Google, Vulkan 1.3.0 (SwiftShader Device (Subzero)), SwiftShader driver)` + `opengl: disabled_off`，
是明写的「软件渲染」。根因是镜像里**没有 Vulkan ICD**，ANGLE 只有内置 SwiftShader；
显式 GPU 身份覆盖在软件上下文也被跳过（上游规则如此，实测印证）。

修复：镜像装 `mesa-vulkan-drivers` + `libvulkan1`；入口脚本探测到 `/dev/dri/renderD*` 才追加
`--use-gl=angle,--use-angle=vulkan`。**刻意不写进默认参数**——无 `/dev/dri` 的宿主上加这两个参数会让
`getContext('webgl')` 直接返回 `null`，比软件渲染更糟。

修复后（NAS，AMD 核显）：
`ANGLE (AMD, Vulkan 1.3.230 (AMD Radeon Graphics (RADV RENOIR)), radv)`，maxTex 16384，
`opengl: enabled_on`、`gpu_compositing: enabled`。

> 想让容器吃到真显卡，compose 里要取消注释 `devices: - /dev/dri:/dev/dri`。
> 没开也不会坏：WebGL 仍可用，只是渲染器是软件的。

## 三、注释与文档订正

- 订正 `src/browser.js` 里「种子统一生成插件 / CPU / 内存」的不实注释；
- 补注 **headful 必须 `viewport: null`**：Chromix 的 screen 几何跟随传给 renderer 的 viewport，
  给固定值等于把 screen 锁死（实测默认 1280×720 会造出「窗口比屏幕还大」的自相矛盾）。
