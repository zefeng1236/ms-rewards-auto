# 0.15.10：补上「攒够多少分就提前领」的入口，并让它看得懂

修 0.15.9 的两个界面问题。**功能本身一直在，只是用户找不到、也看不明白。**

---

## 一、为什么会有「检测到 300 积分领取怎么没有」这个问题

「阈值补领」从 0.15.9 起就写好了：每天**首次运行**和**收工**各读一次「可领取」金额，
攒够阈值就立刻领掉，**不必等「每隔 N 天」的间隔**。

但设置页里**根本没有这个输入框**。所以你只看到「收取节奏 → 每隔 N 天（默认 7 天）」，
自然要问：那 300 分那个呢？

而且还有第二层遮蔽：整块节奏配置被「定期收取积分」开关包着，
**开关没打开时，连"有这功能"都看不到。**

## 二、现在的样子

设置 → 任务全局设置 → 任务开关，在「收取节奏」下方：

```
攒够多少积分就立刻领（阈值补领）
┌──────────────────────────────┐
│ 300                        分 │
└──────────────────────────────┘
每天「首次运行」和「收工」各查一次可领取金额，攒到这个数就立刻领掉，不必等间隔天数
当前：攒够 300 分就提前领；填 0 可关闭这道补领
```

- **单位写在框里**（分）—— 原来只给一个裸 `300`，看不出是积分、天数还是次数
- **随值提示**会跟着变：填 `0` 时显示「已关闭这道补领，想恢复就填一个正数」
- 该项**不再被「定期收取积分」开关藏起来**：开关关着也显示，并说明「本项不会生效」

## 三、顺手修掉一个静默 bug

阈值收口原来写的是 `Math.max(0, Math.floor(Number(x)) || 0)`。

旧配置里没有这个字段时：`Number(undefined)` = `NaN`，而 `NaN || 0` = **0**
→ 判定「阈值补领已关闭」。

**等于给所有存量用户凭空关掉了这个功能**，而界面上又看不到这一项，根本无从发现。

现在改为：字段缺失或非数字 **回落 300**，只有**显式写 0** 才是用户主动关闭。
主进程与界面用同一套规则。

## 四、桌面专属任务仍暂缓上线

入口还在，但置灰并标「测试中 · 延迟上线」；主进程探测与执行全部拦住，
推送汇总也不输出该行。测试完成后会单独说明开放时间。

## 升级提示

- 本版改动含主进程与渲染层，**需要重启软件**。
- 之前开过 Windows Hello 的话：若 PIN 解锁提示「没有免密凭据」，
  **用密码解锁一次**即可自动重建。
- 「定期收取积分」开关没打开时，阈值补领不会生效（这是设计如此，不是 bug）。
