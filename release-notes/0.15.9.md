# 0.15.9：指纹浏览器「取消兜底」、弱密码开关、启动密码与 Windows Hello PIN 解锁

这一版把「安全」这一块补齐了，同时纠正了上一版一个**方向做反**的开关。

---

## 一、新增：取消普通浏览器兜底（只用指纹浏览器）

上一版我把它做成了「停用内置内核、改用普通 Chromium」——方向反了，本版按正确语义重做：

| 开关 | 效果 |
|---|---|
| **取消普通浏览器兜底**（开） | **不许**回落普通 Chromium。指纹浏览器未安装/损坏/未启用 → 本轮任务直接报错停下 |
| 前提 | 没启用「环境拟真浏览器」时**不允许勾选**，界面直接禁用并说明原因 |
| Docker | 不生效。容器里只有镜像内置的指纹浏览器，本来就没有兜底可取消 |

报错会指出「是你勾了这个开关」以及去哪里改，而不是笼统的「未检测到可用浏览器」——
后者会把人引去装 Chromium，方向又错了。

## 二、新增：允许弱密码（不推荐）

- **默认**：≥8 位，含小写/大写/数字/特殊字符，且强度达到第 3 段
- **开启后**：总长度 **≥6 位**，且必须**同时包含字母与数字**
- 引导页与设置页都能设；开启前必须确认一次风险弹窗
- 主进程保留「≥6 位」硬底线

## 三、新增：下次启动时需要输入密码

设置页加开关。开启后启动跳过系统钥匙串自动解锁，直接落到锁屏。
**输入密码解锁成功后会自动关掉这一项**——它的语义是「这一轮启动要验身份」，验完就该恢复日常免密。

## 四、新增：Windows Hello（本机 PIN / 指纹）解锁

Windows 下可以用系统级弹窗输入这台电脑的 PIN 来解锁，走 WinRT `UserConsentVerifier`。

**必须说清它的边界**：系统只回「验证是否通过」，**不会把 PIN 交给本软件**。
所以它是一道**授权门**——验证通过后仍从系统钥匙串取真密钥。

- 挡得住：别人坐在你电脑前打开这个软件
- 挡不住：恶意程序已经跑在你的 Windows 账户下

（Windows 没有「与 Hello PIN 绑定的对称加密」API，Hello 是认证机制而非密钥派生机制。）

### 本版修掉的三个实测问题

1. **PIN 弹窗被应用窗口压住**：实测应用窗与 PIN 窗确实重叠，Z 序是 `0=应用窗 / 1=PIN窗`。
   改成主动把系统窗提到前台（`SetForegroundWindow` + `AttachThreadInput`）。
   ⚠️ 应用自己置顶反而更糟，`blur()` 过头会让验证窗压根弹不出来——两种错误做法都实测过。
2. **验证通过却提示「没有免密凭据」**：机器上那份 `.vaultkey` 是旧 DPAPI 密文，
   当前 Windows 用户解不开。现在会自动清理失效凭据，并在开启开关/密码解锁时重建。
3. **锁定之后再也没法用 PIN**：`lock()` 里顺手把免密凭据删了。
   现在「清内存密钥」和「删凭据」是两回事——只有关闭 Hello 开关才会删。

## 五、暂缓上线：桌面 Rewards 应用专属任务

这个功能已完成，但本版**暂不开放**：

- 设置页入口**置灰**，标注「测试中 · 延迟上线」
- 主进程探测与任务执行**全部拦住**（老配置里开关是开的也跑不起来）
- 推送汇总不再输出「桌面专属」行

## 六、修复：设置页弹窗看不见

设置页内容容器带 `transform`，手写的 `position: fixed` 遮罩会相对它定位，
弹窗被推到视口外（实测遮罩铺成 3634px 高、top = -2341）。改用项目自带 `Modal`（portal）后正常。

## 升级提示

- 本版改动含主进程，**需要重启软件**。
- 如果你之前开过 Windows Hello：升级后**先用密码解锁一次**，免密凭据会自动重建，之后就能用 PIN 解锁。
- 桌面专属任务的入口还在，只是灰着——等测试完成会单独说明开放时间。
