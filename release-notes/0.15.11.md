## 这一版改了什么

### 界面（2026-11-06 晚）：自定义日期一行 + 点开动画

- 年 / 月 / 日三个下拉改为**同一行**（原来因 `.compat-select` 的 `width:100%`
  各占一整行），按比例分宽；「该日期没有日志」提示改到下一行。
- 选「自定义」时日期区**带动画展开**：高度 + 淡入位移过渡，三个下拉依次淡入，
  切回其它预设时同样平滑收起。尊重系统「减少动画」偏好。
- 无日志日期置灰、脱敏默认关闭等行为不变。

### 补修（2026-11-06 晚）：手动领取「没有日志、也不推送」

用户装测试包后点「🎁 立即领取」，反馈看不到日志、也没收到推送。核对 `app.log`
发现日志其实写进去了，但每行都**没有 `[zefeng]` 账号标签**：手动入口不经 `runner`，
漏了 `logger.setContext()`，而日志面板是按账号 id 过滤的。推送则是因为汇总推送只挂在
`runner` 末尾，手动入口没主动推。

- 手动领取执行前后补上 `setContext` / `clearContext`，日志回到账号详情页
- 成功 / 无待领 / 失败统一推一条「🎁 立即领取结果」；推送渠道异常只记日志、不影响领取结果

同一轮日志还给出真实确认按钮 `2,845 待领取 领取积分`（以数字开头），
旧正则要求以「领取」开头 → 0 命中，随后兜底误点导航栏「兑换」，积分 2845→2845。
已改为分级匹配（strong / weak / deny 单一真源，主文档 / iframe / 落地页共用）+ 真实鼠标点击，
落地页规则收紧不再点「兑换」。

> 重测时请重点看：日志面板是否出现带 `[账号名]` 的 🎁 行、是否收到推送、
> 以及 `已确认对话框按钮「…」` 是否替代了原来的「没找到确认按钮」。

### 领取入口点错整张卡片

2026-11-05 用户日志：

```
🎁 当前可领取：2842 分
找到 1 个领取入口，点击目标「可领取 2,842 领取」（无精确匹配，退回包含匹配）
出现对话框但没找到确认按钮：        ← 冒号后一片空白
点击后未生效（2842→2842）
```

三个原因叠加：

1. **点到整张卡片**：页面上没有文本恰好等于「领取」的按钮，旧逻辑退回包含匹配，
   唯一候选就是整张「可领取 2,842 领取」卡片。「面积最小」排序在只剩 1 个候选时
   完全没法比较 → 点卡片等于没点。
2. **确认弹窗误判**：选择器里的 `[data-rac]` 是 React Aria 给**所有**组件挂的通用属性，
   `find()` 取第一个可见元素常常是空壳 → 日志冒号后空白，确认环节白跑。
3. **第二道保险被跳过**：旧条件 `!clicked && !/dashboard/`，
   弹窗误判（dialog=true, clicked=false）+ URL 仍在 dashboard → 落地页兜底整段不执行。

修复：候选池扩到 div/span（要求确实可点）并按文本长度 + 面积打分，
含数字或「可领取」字样的整卡 **+2000 分重罚**；候选清单打进日志并告警；
对话框只认真正的语义标记、遍历全部候选、按钮清单入日志、补英文 `Claim/Redeem/OK`；
新增 iframe 兜底；落地页条件改为 `shouldTryLanded`。

### 本地安装后请重点看这行日志

```
🎁 候选清单：{"tag":...,"t":...,"area":...}
```

它会列出页面上所有含「领取」的可点元素。如果修复生效，日志应该是：

- 点击目标文本短（如「领取」），**不再**是「可领取 2,842 领取」
- 不再出现「看起来是整张卡片而非按钮」的告警
- 对话框那行不再是空冒号，而是带候选数与按钮清单

> 若仍失败，把 `🎁 候选清单：` 和 `出现对话框…` 两行发我，就能直接定位页面改版后的真实按钮形态。

### 其它

- IP 查询失败不再一律报「空响应」，超时 / DNS / TLS / HTTP 429 / HTML 拦截页分别报错。
- 阈值补领「攒够多少积分就立刻领」入口带单位「分」与随值说明。
- 桌面 Rewards 应用专属任务仍暂缓上线（置灰 + 标「测试中 · 延迟上线」）。
