# 0.15.0：修掉程序在「瞎说」的几个地方

这一版改的三件事，看起来都只是几行字：

- 汇总推送里写「已签入（无额外奖励）」——其实它并不知道有没有奖励；
- 积分活动写「未运行」——其实任务跑完了，只是今天本来就没活动；
- 设置里写着「仅在半透明类预设下有视觉差异」——其实这个滑块处处生效。

它们不会崩、不会报错、日志也干干净净。**唯一的后果是你会按错误的信息去做判断**：
以为签到不给分、以为程序漏跑去查故障、以为某个设置没生效而放弃调整。
这类问题比崩溃难发现得多，所以单独发一版。

顺带修了一个只影响安装包的真 bug：登录页左侧插图从打包里漏掉了。

---

## 一、汇总推送不再编造它不知道的结论

### 签到：去掉「无额外奖励」

以前签到那行是这样的：

```
📅 签入: 已签入（无额外奖励）
```

问题在于**程序其实不知道有没有奖励**。微软的每日签到奖励分是变值，
而这个分数只有在「本次接口调用当场返回了分数」时才拿得到。有两条常见路径拿不到：

- 今天已经在别处签过了（手机端、上一轮运行）→ 程序走跳过分支，沿用上次的值；
- 跨天重置后，程序只知道「今天签过了」，不知道这次给了多少分。

旧文案在这两种情况下一律写「无额外奖励」——**等于凭空断言一个没查到的结论**。
看到的人会以为签到根本不给分。

现在拿不到分数就只说事实，不加任何修饰：

```
📅 签入: 已签入          ← 拿不到分数时
📅 签入: 已签入 +5 分    ← 确实拿到了
```

### 积分活动：「今日无此任务」不等于「未运行」

旧逻辑只看有没有拿到分数，没拿到就写「未运行」。但 earn 页当天**确实没有活动**时，
任务其实正常跑完了——那是「今日无此任务」，跟「未运行」完全是两回事。
写「未运行」会让人以为程序没跑、去排查根本不存在的故障。

现在按真实状态区分：

| 情况 | 显示 |
|---|---|
| 今天本来就没有活动 | `今日无此任务` |
| 做了一部分（受单次数量限制） | `5 分(累计)，还剩 2 个` |
| 全部做完 | `5 分(累计)` |
| 开关关着 | `未启用` |
| 出错 | `失败(具体原因)` |
| 真的没跑 | `未运行` |

「还剩 N 个」这条是顺带修的：以前受限制时只显示累计分，会看到「已完成」
却下一轮又跑一遍，像是 bug。

「每日活动」行是同一个毛病，一并修了。

## 二、安装包登录页左侧空白（dev 正常，只有安装版坏）

一个只在安装包里出现的 bug：登录页左半边的插图不见了。

原因是 0.14.x 打包瘦身时，为了不把本地验证截图打进安装包，加了条 `*.png`
一刀切的排除规则——**把登录页插图一起排掉了**，而且这张图从来没进过版本库。

最麻烦的是**开发环境完全正常**（图能加载、6 种窗口尺寸都量过），
只有在装好的客户端里才看得出来。

- 打包白名单和 `.gitignore` 都改成「先全忽略 + 显式放行运行时真正用到的图」；
- 加了守卫：**自动扫描源码里所有图片引用**，漏放行就直接报错——
  不用再靠人记得同步两处配置。

## 三、面板不透明度的说明文案在说假话

设置页那个滑块下面写着「仅在半透明类预设下有视觉差异」。

实际上**这个滑块处处生效**：界面上的内容卡默认走的就是消费这个变量的那条规则，
并不限于某个预设。按那句提示去理解，会以为自己调了没反应。

改成符合事实的说法：

> 调低让背景更透，调高让面板文字更易读

---

## 四、对外文档里的示例数据自相矛盾

发布说明和更新日志的示例中，IP 换成了演示地址，**归属地和运营商还是真实
VPS 的查询结果**，于是出现「IP 是 8.8.8.8、归属地却是台北」这种对不上的内容。

已按实测值更正，并加了守卫：演示 IP 旁边出现不匹配的归属地就直接报错。
