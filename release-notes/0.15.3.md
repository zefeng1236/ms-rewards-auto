# 0.15.3：修「签入推送显示 5 分、汇总只写已签入」

一个「对不上」的修复版本。核心 bug：签入明明拿到 5 分、推送也写着「+5 分」，
同轮运行的汇总却只显示「已签入」——同一轮运行两套数据。另附更新弹窗定宽与守卫加固。

---

## 一、修复：签入分数「推送显示、汇总不显示」

**现象**：签入推送「✨今日签入奖励：5」，同轮汇总「📅 签入: 已签入」。

**根因**：`state.js` 的 `setTaskDone()` 第一行 `load()` 无条件重读磁盘、覆盖内存，
而任务代码的写入顺序是「先写字段、后标完成」：

```js
state.get().signPoint = Math.max(0, point || 0);  // 内存写入 5
state.setTaskDone("sign", …);                     // load() 把 5 冲回磁盘旧值 -1
```

推送用**局部变量** `point`（所以显示 5 分），汇总读 `state.get().signPoint`
（所以是 -1）。阅读 / 每日活动 / 积分活动 / 搜索共 10 处调用全是同一顺序，
同模式字段都可能被冲。

**修复**：`setTaskDone` 改用 `get()`（仅缓存为空时才读盘），不再覆盖同进程内
已写入的值。另补 6 条自检守卫（5 条行为级跑真实状态序列 + 1 条静态锚定函数体），
反例验证全部变红后才合入。

**今日总分不受影响**：积分合计以服务器返回的今日已得值为准，丢的只是汇总行里
「+5 分」这个明细；升级后下一个运行日自动恢复正常。
